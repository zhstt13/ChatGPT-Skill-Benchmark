# Case 02 — Repository Template Engineering

## Purpose

Evaluate whether a Skill can design a reusable repository template without creating unnecessary complexity.

## Scenario

A team wants a new repository foundation for AI-assisted software projects. The template should support growth, collaboration, maintenance, and future skill integration.

## Expected Skill Behavior

The Skill should:

1. Identify required repository surfaces before creating structure.
2. Separate mandatory rules from optional workflows.
3. Design ownership boundaries clearly.
4. Avoid over-engineering and duplicate documentation.
5. Explain tradeoffs and future evolution paths.

## Required Output From Candidate Skills

1. Proposed repository tree.
2. Ownership model.
3. Documentation strategy.
4. Validation and quality gates.
5. Migration/evolution considerations.

## Evaluation Signals

- Template architecture quality
- Scalability
- Maintainability
- Evidence-based decisions
- Complexity control
